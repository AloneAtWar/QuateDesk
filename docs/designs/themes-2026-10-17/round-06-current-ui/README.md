# 主题探索第六轮：适配当前界面

阶段：设计稿，尚未接入正式应用。分支 `codex/theme-design-explorations` 已合并 2026-10-23 的主分支。入口 `style-explorer.html` 是离线单文件画廊；各主题使用同一批匿名演示账号。此轮已按实际桌面看板校正：四列账号卡、无额外页面主标题、刷新队列默认收起；另有 19 套对应的桌面浮窗效果。

## 当前产品改变了什么

本轮先以合并后实际运行的演示界面截取 `source-snapshot.json`。现在主看板有一条常驻的「即将刷新」混合队列，以及展开后的 5 小时、7 天、1 个月三条周期队列。桌面设置改成「外观 / 账号 / 监控 / 数据 / 系统」五组，外观是默认组。远程页面另有「当前设备显示」，现在仍把主题当作亮色与暗色二选一；安卓 WebView 的初始片段也只传明暗。旧稿的页脚和设置入口需要跟着这套结构更新。

三套新方向：

| 方向 | 核心意象 | 本轮实际变化 |
| --- | --- | --- |
| 航站时刻 | 倒计时航显 | 卡片做成上下翻牌；额度、周期和底部队列共用琥珀色时刻表语言 |
| 等高线 | 地形图 | 卡片成为地图切片，圆环像等高标尺，队列是地图图例 |
| 赤色坐标 | 印刷信息图 | 六个账号有明确编号，紧密网格与红色标尺把扫读变成坐标定位 |

原来的 16 套皮肤均保留原始 HTML，并另生成 `legacy-*.html` 适配当前组件树。第六轮画廊只展示校正后的现版适配稿；历史原稿仍在各轮目录，不再和当前界面混排。每套主题保留账号同心圆、全部周期、四列顺序和默认收起的刷新队列，仅调整各自的主色、字体、材质与组件形态。第一轮四套偏配色的方向适合作为默认亮暗的衍生；第二至第五轮的完整皮肤仍可作为独立主题。此处是视觉适配验证，尚未实现运行时主题系统。

## 主题入口与明暗

桌面保留右上角「设置」入口，外观页由明暗下拉改成可预览的主题库。主题选择是一个决定；“固定主题 / 跟随系统”是另一个决定。固定时主题作者声明亮或暗的有效模式，不能强行反色；跟随系统时用户分别选择亮色主题与暗色主题，没有选择时回退至默认亮色/暗色。桌面浮窗继承桌面已解析的主题 ID，而不是保留一套独立的明暗选择。

### 桌面浮窗与看板成对设计

`widget-companions.html` 把本轮 3 套新方向及 16 套现版适配主题的浮窗放在一起。选择左侧主题，可查看双周期、加长三周期告警、额度不可用和最短长度收起状态。这里依据 `src/main.jsx` 的 `WidgetRow` 与 `src/styles.css` 的实际单行结构绘制：350×52 是基准尺寸，当前默认缩放与长度均为 90%，实际约 284×47；长度可在 60%–150% 间调整，大小在 80%–300% 间调整。视觉稿为便于比较统一用 100% 大小，分别展示 90%、120% 和 60% 长度。浮窗继续每 6 秒轮换账号，滚轮手动切换，双击展开主看板。

主题可以为浮窗提供高辨识度但低密度的材质：例如航站时刻的翻牌分隔线、等高线的地图纹理、赤色坐标的刻度边线。这些细节不应挤占账号名、额度数值与告警状态。多窗口账号在可用宽度里尽量保留全部周期；排不下时沿用现有顺序：先缩／藏标签，再逐个收倒计时，最后从最长周期起收额度窗口，至少保留一个。短版稿表现这一最终收起状态，主题不能改变收起优先级。主题包里的浮窗专用 token 应覆盖窗口背景、行卡、描边、主文字、芯片、芯片标签／读数／次级字、账号标签、在线灯与告警灯；缺字段时使用宿主可读的亮／暗默认值。正式接入时需在真实 Electron 浮窗与设置预览中验证缩放、拖动热区、对比度和窗口更新瞬间的闪烁。

Android 原生外壳负责设备列表、扫码和连接错误，可保持系统／亮色／暗色三种克制外观。额度看板是电脑提供的 WebView 页面，由网页独立选择完整设计主题。两层不相互改写主题偏好；桌面与 WebView 可以共享主题定义和账号组件，但是否选同一款是另一项明确的偏好。这样新增主题无需在 Java 原生页和网页各实现一次。

状态栏和导航栏在原生页依据外壳明暗显示，进入 WebView 时只依据当前网页底色调整图标可见性，返回时恢复外壳设置；这不需要「外部明暗和内部一致」开关。现有 Android 定时把 `lightTheme` 与 `data-theme` 双向校正的逻辑不适合作为未来多主题协议，后续实现需分离为系统栏适配与独立的主题存储。

桌面主题设置可以从 `theme: 'light' | 'dark'` 迁移为 `themeId` 与 `appearancePolicy`（fixed/system），跟随系统时再分别保存亮色和暗色主题 ID。WebView 另存自己的 `themeId`；旧明暗值无损映射为默认亮色/默认暗色。默认两款沿用现在的克制视觉，历史配置与同步包依然可读。

## 自定义主题需要包含什么

普通用户从一个内置主题复制，只需填写名称并修改可见参数：亮暗模式、颜色层级、字体、形状、材质强度、额度圆环、状态、队列、抽屉与浮窗。导出为 JSON 草稿即可；高级作者可提交 `.qdtheme` 包，包含必需的 `theme.json`，可选的 `theme.css`、本地字体/纹理/背景和预览图。主题包不能包含脚本、网络加载资源或改变业务数据与操作顺序的布局规则。完整字段示例沿用 [`../round-02/custom-theme.example.json`](../round-02/custom-theme.example.json)，此轮须补足如下主题目标：

| 目标 | 主题作者提供或继承的内容 |
| --- | --- |
| 主题身份 | schemaVersion、id、name、version、author、extends、最低宿主版本、`mode` |
| 主看板 | 窗口/标题栏/卡片/悬浮层/文字/边框/控件/焦点的 token；字体与形状 |
| 数据图形 | 圆环、轨道、中心读数、周期圆点、告警状态，均须保留文字辅助 |
| 当前新增区域 | 混合刷新条、三周期队列、展开把手、可滚动条目与空队列回退 |
| 设置与弹层 | 五组设置页签、主题卡片、输入框、预览草稿、弹层与通知 |
| 多端 | 桌面浮窗的专用语义 token、紧凑材质及正常／告警／不可用状态；WebView 响应式变体；Android 原生外壳独立维持克制亮暗，系统栏在网页显示期间适配当前页面 |
| 素材 | 可选背景、纹理、字体、SVG 装饰；所有路径相对主题包，缺失时回退纯色 |

导入后先预览真实数据和四种关键状态（正常、告警、不可用、聚焦），以及当前的刷新队列、设置抽屉和手机窄屏。保存后才应用；取消或导入失败恢复原主题。对比度和缩小视口时的字号应作为导入检查的一部分。主题 CSS 只能覆盖公开插槽及装饰，不能隐藏额度、账号名称、队列或警告信息。

## 本轮文件与局限

`departure.html`、`contour.html`、`coordinates.html` 是新方向；`legacy-*.html` 是旧皮肤的当前界面适配；`widget-companions.html` 是对应的 19 款浮窗及关键状态；`appearance-flow.html` 展示桌面主题库与独立的 Android 原生设备页；`baseline-shots/` 是实际演示界面截图。`build.mjs` 从本轮快照与旧稿重建全部 HTML，并调用 `build-widget.mjs` 生成浮窗稿。主看板的账号与读数来自浏览器 demo；浮窗页使用同一组匿名账号名与用于状态比较的演示读数。账号卡、同心圆和底部队列沿用真实组件的内容与布局；设计页只有队列把手可切换展开状态，浮窗页的主题选择可切换预览，其余按钮不连接真实数据。Android 原生页依据 `D:\devlopment\QuotaDesk-Android` 的源码绘制示意，没有修改安卓实现。
