# Quota Desk：完整视觉主题提案 · 第二轮

阶段：主题首屏效果探索；未接入正式应用。第一轮配色稿已被本轮方向取代，第一轮 JSON 格式也不作为最终约束。

## 设计目标

保留当前亮色、暗色作为「默认」主题的两个模式；额外主题提供完整的视觉语言，不再只是换色。用户首要任务仍是扫视账号、剩余额度和重置时间。设计北极星：**让桌面看板有个性，同时让额度比装饰更容易被看到。**

品类是桌面额度监控工具，不是宣传页。真实内容沿用项目浏览器演示快照的六个匿名账号，同一批数据用于三个候选。账号 Logo、对象顺序、额度单位、周期与连接状态保留。为了在一张图上展示材质与字形，本轮统一使用 1200×820、三列两行和放大后的阅读字号；这是比较用画布，未决定主题可以改变正式应用的网格布局。

项目现有 DESIGN.md 是默认主题的基线。本轮用户明确要求探索额外主题，字体、表面、形状和视觉效果属于探索范围；不覆盖已确认的默认主题约定。

## 三套新主题

| 主题 | 引擎与识别点 | 字体和控件 | 边界 |
| --- | --- | --- | --- |
| 工程蓝图 | 从「监控仪器」出发；细网格、制图角标、刻度圆环；硬边半透明面板 | Consolas 等宽数字、直角按钮、细线分区 | 背景线不得穿过正文；角标只做表面装饰 |
| 纸本编辑 | 从「额度账簿」出发；纸张颗粒、墨线、偏移纸页阴影 | Georgia / 宋体账号标题与数字，印章式标签 | 纹理透明度低；文字与金额保持锐利完整 |
| 极光玻璃 | 从「常驻桌面的环境光」出发；弧光背景、磨砂表面、透亮圆环 | 轻字重额度、圆润卡片、胶囊控件 | 卡片有稳定底色；不让壁纸决定文字对比度 |

这是同一功能的三套主题，不是三套产品架构，因此有意保持账号内容、导航与卡片网格相同；差异体现在材质、字体、轮廓、控件和图形处理。图像不承担业务信息，本轮用 CSS 与内嵌 SVG 制作几何弧光和纸纹，不需要额外生成位图，也不依赖网络图片或字体下载。

## 内置主题怎么组织

建议首批：默认（已有亮/暗）、工程蓝图（暗）、纸本编辑（亮）、极光玻璃（暗）。不要为每个主题机械生成深浅两版，材质不一定在相反明暗下成立。选择器将「主题」与「明暗策略」分开：

- 主题库：卡片展示真实缩略图、名称、支持的亮/暗模式；默认主题原样保留。
- 明暗策略：手动明暗或跟随系统。跟随系统时分别记住用户选定的浅色主题和深色主题，避免把纸本强行反色。
- 桌面浮窗默认沿用主窗口主题，主题作者需提供浮窗视觉；远程页面保留单独偏好，缺字体或图形能力时使用继承主题回退。
- 入口继续放在「设置 → 通用 → 外观显示」，不新增主导航。创建和导入后先预览，保存并应用后才写入配置。

## 自定义主题要放什么

建议同时支持简单 JSON 和完整 `.qdtheme` 包（ZIP 容器），使用同一份 manifest。完整包如下：

```text
my-theme.qdtheme
├─ theme.json          必需：身份、继承关系、样式参数与能力声明
├─ theme.css           可选：进阶表面、图形与控件皮肤
├─ preview.png         可选：作者预览，导入后仍生成本机实际缩略图
└─ assets/             可选：背景、纸纹、字体和装饰 SVG
   ├─ paper.webp
   ├─ backdrop.webp
   └─ display.woff2
```

没有图像也可以制作完整主题，工程网格、弧光、纸纹均可由预设效果实现。不要要求每个主题作者提交整套界面截图、每个厂商 Logo 或背景壁纸。图片是可选风格资产，不是主题成立的必要条件。

### theme.json 的内容分层

| 层 | 内容 | 缺省行为 |
| --- | --- | --- |
| 身份 | schemaVersion、id、name、version、author、description | 名称等核心身份必填，其余可选 |
| 继承与模式 | extends、mode、主题包最低宿主版本 | 只能继承内置主题，先不支持任意继承链 |
| 颜色 | 窗口、各层表面、文字四层、边框、控件、强调、焦点 | 只覆盖填写项，继承其余值 |
| 字体 | 正文、标题、数字字族；本地字体资源和系统回退 | 正文使用系统中文字体；保留用户字号偏好 |
| 形状 | 卡片/按钮/输入/标签的圆角、描边宽度与样式 | 继承现有组件，不暴露任意布局规则 |
| 材质与效果 | solid / paper / glass / blueprint；纹理强度、透明度、模糊、阴影、发光 | 无素材和效果支持时回退实色表面 |
| 图表 | 圆环颜色与粗细、轨道、外缘刻度、模型图颜色 | 默认沿用原来按圆环层级的颜色，不能按周期自动重排 |
| 状态 | 正常/告警/不可用的前景、背景和边线 | 状态文本与图标保留；告警不只靠颜色区分 |
| 浮窗 | 背景、行表面、标签、数值、材质强度 | 继承主主题，可专门减少模糊与阴影 |
| 素材与能力 | assets 路径、preview、stylesheet、使用的效果类型 | 相对路径引用包内文件，素材缺失时回退继承值 |

### 两种作者体验

普通用户：从内置主题复制，使用颜色、圆角、字体选择和材质强度滑杆，导出一个 JSON 即可。材质选项只显示当前预设支持的字段，不把所有 CSS 参数摊给用户。

进阶作者：添加 theme.css 和 assets，覆盖宿主公开的主题插槽。CSS 是高级可选项，JSON 参数是稳定接口。作者不需要了解每个 React 组件的私有类名。

建议公开的插槽：app-background、titlebar、surface-account、quota-ring、quota-track、quota-core、control、input、tag、drawer、dialog、tooltip、chart、widget、ticker。伪元素用于网格/角标/纹理等装饰。字体、颜色、圆角和层级由稳定变量连接这些插槽。

主题 CSS 限定在根部主题作用域及公开插槽内；设置抽屉和 portal 弹层也必须获得相同作用域。主题不能控制对象顺序、网格列数、可见性、按钮命中范围或真实数据。样式和素材使用包内资源，不装入脚本或外部资源。导入时报告不支持的字段与缺失素材，不默默吞掉整份配置。

### 预览、保存与失败恢复

1. 创建/导入后显示草稿，不立即替换已保存主题。
2. 预览主看板、告警账号、抽屉、输入焦点、图表、浮窗及缺素材状态。
3. 检查文字和控件在实际表面上的对比度；玻璃主题检查背景最亮处，纸纹检查纹理最深处。
4. 有问题时定位到具体颜色或素材；输入和草稿保留，可以恢复继承值。
5. 保存成功才应用到持久配置；失败继续停留在草稿。取消预览、Esc 或重新启动应恢复上次保存主题。
6. id 重复时允许覆盖已安装版本或另存副本；更新包保留用户选中的主题引用。删除当前自定义主题回退到默认同明暗版本。

### 动效提案

正式实现时：主题切换的表面过渡约 180ms；主题卡片选中态约 120ms；预览展开约 180ms。不常驻播放扫描、闪烁或漂移，不在每次额度刷新时重新播放装饰。遵守系统减少动态效果偏好。本轮是静态首屏，未实现或验证这些动效。
