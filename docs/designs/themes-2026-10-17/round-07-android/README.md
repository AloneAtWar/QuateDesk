这轮增加三种具有独立视觉语言的主题。每种都包含桌面账号看板、Android 原生设备列表、手机 WebView 额度看板和手机主题选择界面。打开 [总览](style-explorer.html) 比较全部效果，先看每款的“三端全景”，再进入单屏看细节。此前的桌面方案仍保留在 [第 06 轮](../round-06-current-ui/style-explorer.html)。

## 基于当前产品的边界

Android 仓库 `D:\devlopment\QuotaDesk-Android` 中，设备列表、扫码和连接状态由 `MainActivity` / `ScannerActivity` 的原生界面绘制；账号额度看板由桌面端提供的远程页面在 WebView 中绘制。因此主题必须覆盖**原生层和网页层**，而不只是给远程网页换 CSS。当前两层保存/同步的是 `light` 或 `dark`：Android 使用 `PREF_LIGHT_THEME`，进入网页时通过 URL 的 `#theme=` 传递，并在加载后监听/校正 `data-theme`；网页还暴露 `window.__qdSetTheme`。桌面远程页面和配对页各有一个亮暗按钮。如今若加入多款完整主题，仅同步亮暗会丢掉具体风格。

本轮草图以 390 × 844 的手机视口和 1200 × 820 的桌面视口绘制。手机额度页的当前基线截图也放进总览，以便比较字级和信息密度。原生页是按 Android 源码重构的设计示意；本机没有连接 Android 设备或可用模拟器，因此它不是运行中 App 的实拍。扫码取景框在全景图中是布局示意，相机画面仍采用中性暗底，主题控制准星、帮助文案和操作反馈。

## 主题交互的建议

桌面端把顶栏现有亮暗控制改成“外观”入口。Android 的原生设备页与 WebView 顶栏同样提供“外观”，都打开同一份主题列表，选择结果先预览再应用。外观策略允许固定一款主题，或分别指定亮色和暗色款；“跟随系统”仅决定激活哪一款，而不是覆盖主题的字体、形状和构图。系统状态栏/导航栏根据最终主题的 `mode` 自动设置底色和图标明暗，独立的“内外明暗一致”开关便失去意义。配对、离线、错误和空列表页也要继承当前主题，但始终优先保留清晰的连接和重试操作。

建议把同步对象从单个 `lightTheme` 布尔值提升为 `{ themeId, mode, appearancePolicy }`。Android 在 WebView 首次加载之前传入这组值，网页首帧就能使用正确主题；网页中的选择反馈给原生层，返回设备列表时仍保持同一 `themeId`。旧版 Android / 旧版电脑端可继续接受现有 `#theme=light|dark` 与 `__qdSetTheme`，未知主题 ID 回退到与当前亮暗相符的默认主题。通信与持久化应传白名单 ID，不在配对链接里携带任意 CSS。

## 自定义主题要提供什么

用户自定义的最小内容不应只是两组颜色。可以让主题包声明：

- 基本信息：稳定 ID、名称、作者、预览图、版本和明暗属性。
- 颜色语义：背景、表面、主/次文字、边框、强调色，以及成功、警告、错误、禁用、焦点和图表系列色；每项含可读性校验。
- 排版与形态：字体或安全回退、字重/字阶、圆角、描边、间距、阴影和动效强度。
- 组件变体：账号卡、余额图、设备卡、刷新队列、主题选择项、扫码准星、空/加载/错误状态的样式 token 或受限模板。
- 适配与回退：桌面/窄屏断点，Android 原生控件映射，是否提供亮暗双版本；缺失值回退到内置基础主题。

普通用户可以从“复制一款内置主题”开始，在可视化编辑器里调这些语义项，并看到桌面、设备列表、手机额度页三屏联动预览。高级用户再导入/导出 JSON 和受限图形资源。原生界面不应执行用户 CSS/JS；跨端共享语义 token，再由各端映射为自身组件。仅给一张壁纸或任意 CSS 文件会让原生设备页、状态反馈与系统栏无法可靠匹配。

本目录只交付设计探索，没有改动 Android 或桌面应用的运行代码。`build.mjs` 可重建独立页面与总览清单；效果截图在 `shots/`。
