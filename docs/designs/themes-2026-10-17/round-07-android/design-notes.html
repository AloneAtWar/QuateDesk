07 / DESIGN CONTRACT / DESKTOP + ANDROID

主题身份要贯穿设备页与额度页

当前安卓原生层画设备列表、扫码和连接状态，桌面端远程网页画额度看板。现在两层只传亮暗；多主题加入后需要同步具体主题 ID，再由各端映射相同的视觉语义。

一条清晰的外观流程

桌面与手机顶栏的亮暗图标改为「外观」。原生页和 WebView 打开同一份主题选择；应用后返回任一界面都维持同一款。

固定主题分别指定亮色 / 暗色跟随系统

跨端通信和旧版兼容

存储和传输 { themeId, mode, appearancePolicy }。进入 WebView 前设置首帧主题；网页变更回写原生层。未知 ID 回退对应亮暗的内置基础款，旧版继续识别 #theme 和 __qdSetTheme。

用户自定义主题的必备内容

  • 名称、ID、版本、作者、预览与明暗属性
  • 语义色：文字、表面、状态、焦点、图表
  • 字体、字阶、间距、描边、圆角、阴影与动效
  • 账号卡、余额图、设备卡、刷新队列、扫码与异常态
  • 桌面 / 窄屏规则及缺项回退

手机端的实际约束

扫码相机保持中性暗底，主题只控制准星与提示。状态栏和导航栏从当前主题的明暗属性取色，不再提供独立的「内外一致」开关。配对、空列表、离线和重试状态都沿用主题。

自定义主题通过共享 token 映射到原生组件；不在配对链接里传任意 CSS 或 JS。

这轮是设计探索稿；原生画面按 Android 源码重构，本机无安卓设备或模拟器，尚非运行中 App 实拍。
