# WebDAV 用量档案同步

入口：**设置 → 数据 → WebDAV 云同步**，点击区块展开配置。仅桌面客户端提供配置；不需要 Quota Desk 账号或官方服务器。

## 配置与使用

1. 填写 WebDAV 服务地址、用户名、应用密码和同步目录。服务地址应使用 HTTPS；仅回环地址允许 HTTP，用于本机测试。同步目录相对于服务地址，可自动创建。
2. 创建至少 6 个字符的同步加密口令，不要求大小写、数字或特殊符号组合。所有设备使用同一个目录和口令；网盘的应用密码与同步加密口令是不同的字段。
3. 点击“测试连接”可直接测试当前填写的配置，无需先保存。按钮下方显示正在测试、连接成功，或连接失败及具体原因；测试不会保存或启用配置。确认后保存配置，勾选自动同步并保存即可工作，也可点击“立即同步”。

自动上传按最近一次成功上传检查起间隔 24 小时执行。数据没有变化时只检查，不重复上传；手动同步可以提前上传。其他设备的更新每 30 分钟检查一次，无更新时根据已验证的版本和发布记录跳过快照下载；失败后 15 分钟重试。调度记录落盘，重启后沿用；应用关闭期间不执行，下一次启动补做已到期任务。

每台设备仅上传本机扫描的完整档案，不转发已导入来源。接收到的档案与手动导入使用相同校验和合并规则：按来源 ID 独立存储，新版完整替换该来源，旧版或重复内容跳过，同版本冲突停止更新，本机来源不导入。来源自己的修正、删除或空快照能够在后续版本反映；网络错误、缺失文件或被删除的云端文件不会删除本地保存的档案。可在“用量档案”查看每个来源的版本、范围和导入时间，重命名或暂停计入汇总。

删除导入来源时，同时在本机暂停从 WebDAV 接收它。暂停列表位于云同步设置，可恢复接收；不会删除云端文件，也不影响其他设备。手动导入仍可使用。切换到另一个服务地址、用户名或目录会重置同步进度和暂停列表，但保留所有本地档案。

## 加密与数据范围

同步内容为规范化的 CLI 用量记录、来源名称和项目标签，与用量档案导出范围一致；不包含账号凭据、登录快照或对话正文。项目名称等内容也位于密文中。云端路径包含随机来源 ID、版本号和上传月份，存储服务仍可观察这些信息、文件大小和修改时间。

JSON 先 gzip 压缩，再使用 AES-256-GCM 认证加密；每份文件生成新的 16 字节盐和 12 字节 nonce，使用固定参数 scrypt（N=32768、r=8、p=1）从共享口令导出 256 位密钥。格式与算法版本作为附加认证数据。拒绝未知格式、畸形参数和认证失败的文件，并限制下载及解压大小（单份压缩内容最多 64 MiB，解压后最多 256 MiB）。

WebDAV 应用密码和同步加密口令只在主进程使用，保存在独立 `usage-sync-config.json`，通过 Electron `safeStorage` 加密后落盘，不包含在普通账号数据导出中；渲染进程只能获得“是否已保存”标记。系统凭据加密不可用时拒绝保存。`usage-sync-state.json` 只保存调度、已接收版本和暂停来源等进度。

云端初始化时创建加密的 `sync-key.json`，之后先验证口令再同步。首次配置使用 `MKCOL` 创建 `key-init/` 目录，只有创建成功的设备可以写入校验文件，其他设备等待并验证已有文件，避免并发初始化时相互覆盖。`key-init/` 会保留，不能把它当作临时文件删除。如果初始化在写入校验文件前中断，持续重试仍提示初始化未完成时，请改用新的空目录；不要删除或覆盖现有校验文件来重设口令。已有档案但缺少该文件时也会拒绝重新初始化。

当前版本不提供口令轮换、云端清理或本机来源恢复；要换口令，请选择新的空目录并在所有设备重新配置。丢失口令后无法从云端解密恢复，仍可由保留本机档案的设备导出。复制数据库后同时运行会共享来源 ID，不适合作为新设备初始化方式。

## 文件协议与故障处理

新版协议按来源和 UTC 上传月份存放文件：

```text
sync-key.json
key-init/
v2/<source-id>/<YYYY-MM>/r<revision>.<random-id>.snapshot.json
v2/<source-id>/<YYYY-MM>/r<revision>.<random-id>.commit.json
```

每次发布使用新的随机文件名：先 PUT 完整快照并回读核对，再写入加密的完成标记并回读核对。其他设备只接收有完成标记的快照，验证目录身份、来源、版本和内容摘要；没有共同修改的“最新版本”文件，因此不要求 `If-Match`、`If-None-Match` 或 ETag。目录发现使用 `PROPFIND Depth: 1` 逐层读取规定的路径，忽略外部地址和不符合命名规则的条目。

读取同一来源时，在所有月份中选择最高版本号，不依赖上传时间或设备时钟判断新旧。同版本、同内容的重复发布可以安全跳过；同版本存在不同内容时停止该来源更新并提示冲突，避免把复制档案库的两个设备混为一个来源。

新版保留已发布的历史快照和完成标记，不自动删除云端档案。上传中断时可能留下没有完成标记的快照，它不会参与汇总；重试使用新的文件名，不影响此前完整版本。发布响应丢失时，下次同步会重新发现已完成的版本。本机来源的快照缺失或损坏时，可通过“立即同步”校验并重新发布；其他来源的文件异常会保留本地档案并提示重试。

客户端仍可读取旧协议的根目录索引 `<source-id>.json` 及其快照，新发布统一使用 `v2/`。旧文件会保留。所有参与同步的设备都应升级到支持新版协议的客户端，旧客户端无法读取 `v2/` 中的新版本。

连接需支持 MKCOL、PROPFIND、GET、PUT 和 DELETE；DELETE 用于清理连接测试创建的探测文件。请求不携带浏览器 Cookie，不跟随重定向；发生重定向应改填最终地址。客户端使用应用网络代理设置。一次失败会保留已提交的来源更新，记录错误并重试，不进行整库回滚或远端删除传播。

自动化测试使用本地 WebDAV 服务覆盖多设备全量更新、重复与旧版、并发初始化、口令错误、密文损坏、发布中断、响应丢失、调度持久化、暂停接收和凭据隔离，并验证不提供条件写入或 ETag 的服务。真实网盘的具体配额、权限和兼容性以“测试连接”和实际同步结果为准。

运行 `npm test` 执行自动化测试；`npm run test:sync:electron` 额外验证真实 Electron `net.fetch`、系统凭据加密与数据库 Worker 的双设备流程，仅使用临时合成数据和回环地址服务。
